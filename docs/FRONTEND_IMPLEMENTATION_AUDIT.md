## Блокеры backend по приоритету

### P0

1. **Очередь «После встречи».** Нужен `GET /after-meeting/queue/?host_id`:
   - группы `outcome_required`, `no_next_step`, `awaiting_decision` по правилам компании;
   - в каждой записи — встреча, сделка, этап, сумма, следующий шаг.

   Плюс `POST /after-meeting/{meeting_id}/process/` — итог, договорённости и задача одной транзакцией. Права — как у встреч. Сейчас очередь собирается на frontend из нескольких запросов.
2. **Фильтр `outcome_required=true` в `GET /meetings/`.** Сейчас признак считается на frontend по всем страницам.
3. **Кабинет, блок A (`team/today`).** Нужны поля:
   - `meetings_to_confirm`, `next_to_confirm_at`;
   - `meetings_rescheduled` (с датой и без), `meetings_cancelled`;
   - `calls_answered`, `conversations_30s`, `call_minutes`;
   - `waiting_replies`, `max_wait_hours`;
   - `tasks_unassigned`;
   - хвосты: перенос без даты, после встречи без шага, «состоялась», но сделка не двинулась;
   - список «Что делать сегодня»;
   - оценка дня.
4. **Рабочий календарь в `team/plan-fact`.** Сейчас дни календарные. Нужен учёт выходных, отсутствий и рабочих суббот, а также поля `per_day_needed`, `meetings_held_needed`, `meetings_to_book_needed`.
5. **«Срез на планёрку».** `POST /team/snapshots/` (снимок блока A с меткой времени и отправкой в Telegram) и `GET /team/snapshots/` (история, 13 месяцев).
6. **Счётчик «N дней без активности»** в `team/inactivity`.
7. **`reopen` сделки.** Сейчас сделка остаётся на закрывающем этапе со статусом `open`. Нужно возвращать её на последний открытый этап.

### P1

1. **Карточка one-to-one.** `GET /team/members/{user_id}/card/?from&to`:
   - план-факт, оплаты, доходимость, CR встреча→продажа и звонок→продажа;
   - активность по дням, дни без активности;
   - сравнение с прошлым периодом и средним по отделу.
2. **Воронка.** `GET /team/funnel/?pipeline_id&from&to`:
   - остатки по этапам, медиана возраста, число старше порога;
   - конверсия между этапами, динамика к прошлой неделе;
   - потери по причинам по месяцам; «тёплые» без движения.
3. **Гигиена.** `GET /team/hygiene/`:
   - «ничьи» и просроченные задачи по возрасту;
   - сделки без ответственного;
   - оплаты без даты и без продавца;
   - дубли.
4. **Фильтры звонков** в `GET /telephony/calls/`: `owner_id`, `subject_type`/`subject_id`, `date_from`/`date_to`, `search`, несколько `status`.
5. **Поиск** (`search`) в `GET /activities/` и `GET /meetings/`; фильтр встреч по клиенту (`customer_id`, в том числе через сделку).
6. **Выгрузки по блокам кабинета** (`report_type`: today, plan_fact, hygiene) и недельные и месячные сводки по расписанию.
7. **«Мой день».** Заработок менеджера, дневная динамика `paid` и `sales` по дням месяца, направления.
8. **«Фокус».** Операции `snooze` и `dismiss`, приоритет, «ждут ответа» из чатов.
9. **Статус доставки уведомлений в Telegram.**

### P2

1. Итоги one-to-one: CRUD с доступом только для руководителей.
2. «Оценка ИИ неверна» с комментарием; покрытие оценками звонков.
3. Справочник причин дисквалификации лида; `team_id` в ответе лида.
4. Признак «перенесена с прошлых дней» у задачи.

## Внешние интеграции

- **Телефония:** автоматическая запись звонков, линии, обрывы.
- **Мессенджеры:** чаты и «ждут ответа».
- **Telegram:** срезы, алерты, временные пароли.
- **ИИ-модуль** (другой разработчик): сводки, оценки, разбор, ИИ-помощник.

## Решения владельца продукта

1. **Пороги оценки дня 5/4/3/2 и светофора.** Кабинет §«Оценка дня» помечает их как предложение.
2. **Неназначенные («ничьи») задачи.** Нужны ли они вообще: backend всегда назначает задачу автору.
3. **Ручное подтверждение встречи.** Реализовано (`source=manual`), но в ТЗ кабинета это открытый вопрос.
4. **Определение «эффективности» звонков** и подписи к обороту: включение полной оплаты, вычет возвратов.
5. **Обязательность причины отказа.** Закрывать ли как проигранную без справочника причин — сейчас причина вводится текстом.

- «без итога» во «Встречах» и в «После встречи» отбирает backend;
- «Обновлено» в «Списке» и в карточке клиента — реальная дата изменения сделки;
- «Материалы» — список инструкций из ТЗ со ссылками на Google Drive.

Скрыто в режиме api (нет backend, прямой URL ведёт на стартовую страницу роли):

- «Отчёты дня», «Работа над ошибками», «Рабочее пространство», «ИИ-помощник»;
- карточка менеджера `/team/[id]`;
- вкладка «Звонки» в карточке сделки;
- фильтр «Без исполнителя».
