## По ТЗ (28.10.2026)

- **ТЗ.docx — главный источник продуктовых требований.** Скриншоты — референс структуры и функций, не бренда: чужие название, логотип и тексты не копируем.
- **Навигация — верхняя панель, как на всех скриншотах ТЗ.** Основные разделы, «Все разделы» и кнопка ИИ-помощника. Это заменяет боковое меню первого этапа.
- **Стартовая страница — «Мой день».** У менеджера — личный план, заработок и дела. У руководителя — результаты отдела (виджеты первого этапа). Одна страница, разные раскладки по ролям — это и есть модель настраиваемых рабочих пространств.
- **Тёмная тема — основная** (по ТЗ). Светлые токены сохранены без переключателя.
- **«Разбор» переименован в «Работу над ошибками» (рабочее название, 28.10.2026)** — по заданию владельца.
- **Бизнес-правила не изобретаем.** План к сегодня, прогноз, заработок, отбор лидов в «Фокус», рекомендации ИИ и оценка звонков считаются на backend; frontend показывает готовые значения.
- **Левая панель чатов** со скриншотов («Открыли ссылки», «Ждут ответа», переписка) в списке разделов промпта не указана. Отложена до решения владельца.

## Архитектура (технические)

- **Переключатель демо-роли в меню профиля** (cookie + server action, работает только на демо-данных). Позволяет показывать продукт глазами менеджера, РОПа и директора. Это не авторизация.
- **Данные, зависящие от запроса, — внутри `<Suspense>`.** Требование Cache Components в Next 16 для мгновенной навигации: статичная часть страницы показывается сразу.
- **Фильтр по менеджерам — в адресе страницы (`?manager=`).** Ссылкой можно поделиться, кнопка «назад» работает.
- **Не подключённые к backend действия («Отложить», «Убрать из фокуса») показаны выключенными с пояснением**, а не спрятаны и не имитируют успех.
- **Модуль `features/dashboard` остаётся агрегатором «Моего дня».** Виджеты менеджера лежат в `components/my-day/`, отдельный модуль ради одной страницы не нужен.

- **Модули в `features/`, маршруты в `app/`, общие блоки в `components/shared`.** Границы модулей видны по структуре; страницы остаются тонкими.
- **Репозиторий на модуль с двумя реализациями: mock и http.** Демо-данные отделены от реального API; переход на backend не требует менять виджеты. Несогласованные методы выбрасывают `contract_pending`, ничего не выдумывая.
- **Zod для ответов API и переменных окружения.** Ответ backend — внешние данные, их нужно проверять. Типы выводятся из схем, без дублирования.
- **Без TanStack Query на этом этапе.** Главная читает данные в Server Components. Подключим, когда появятся клиентские списки с фильтрами и изменения данных.
- **Recharts через shadcn chart** для графиков. Это стандарт выбранного UI-кита и самая богатая аналитика при умеренном весе. Используется только в клиентских компонентах графиков.
- **Виджеты главной — по конфигурации и через явный реестр.** Это основа настраиваемых рабочих пространств: конфигурация задаёт что и где, реестр — какой код допустим.
- **Каждый виджет — свой Suspense и своя граница ошибок (`catchError`).** Медленный или упавший виджет не ломает страницу.
- **Права в интерфейсе — только для отображения.** Реальные проверки на backend.
- **Демо-роль через `NEXT_PUBLIC_DEMO_ROLE`.** Позволяет посмотреть интерфейс глазами любой роли до появления авторизации.
- **Перенаправление `/` → `/dashboard` в `next.config.ts`.** `redirect()` в странице мешает проверкам мгновенной навигации Next 16.
- ~~`hooks/use-mobile.ts` на `useSyncExternalStore`~~ — удалён вместе с боковым меню (28.10.2026).

## Этап «Продажи, карточка лида, задачи, встречи» (28.10.2026, технические)

- **Контракт backend (JWT Bearer, X-Tenant, snake_case, формат ошибок, limit/offset, деньги строкой) встроен в `lib/api`.** Преобразование имён полей и разбор ошибок — только в API-клиенте.
- **Хранение токенов — httpOnly-cookie сервера Next.js (решение владельца продукта, 28.10.2026; согласуется с backend-разработчиком).** Пару `{ access, refresh }` получает и хранит сервер Next.js; JavaScript страницы токены не видит. В Python backend уходят только заголовки `Authorization: Bearer` и `X-Tenant` — cookie-сессий backend нет. Отклонены: токены в браузере (refresh доступен скриптам, все экраны пришлось бы перевести на клиентскую загрузку) и cookie от backend (противоречит согласованному формату ответа).
- **Токен обновляет `proxy.ts` до рендера страницы.** В Next 16 cookie нельзя записать во время рендера серверных компонентов, а при ротации старый refresh сразу становится недействительным — обновление посреди рендера разлогинило бы пользователя. Серверные компоненты токены только читают (`refreshOnUnauthorized: false`), server actions могут обновлять сами.
- **Один обмен на один refresh-токен** (`exchangeRefreshToken`): параллельные запросы ждут общий результат, он помнится 10 секунд. Работает в пределах одного процесса Next.js — при нескольких серверах нужен ответ backend (вопрос в `API_CONTRACT.md`).
- **Роли backend переводятся в роли интерфейса в одном месте** (`backend-roles.ts`). Добавлена роль интерфейса «Наблюдатель» и права `records.edit`, `records.assign`.
- **Сделка = лид в воронке.** Карточка сделки и клиента — одна страница `/leads/[id]`; все разделы ссылаются на неё через `leadRoute()`.
- **Смена этапа: перетаскивание на компьютере + меню карточки «Сменить этап».** Меню работает с клавиатуры и на сенсорных экранах, где перетаскивание конфликтует с прокруткой. Без новой библиотеки (нативный HTML Drag and Drop).
- **Закрытые этапы (успех / отказ) не показываются колонками доски.** Закрытие — через диалог с обязательной причиной отказа; закрытые сделки видны в таблице с фильтром по этапу.
- **Задачи без группы не выдумываются.** Группы сроков и просрочка приходят от backend; созданные или изменённые в демо задачи собраны в группу «Изменено в демо-режиме».
- **Формы на нативных полях + Zod, без React Hook Form.** Формы пока короткие (до 6 полей); RHF подключим вместе с первой большой формой (настраиваемые поля лида).
- **Подробности задачи — в выезжающей панели, итог встречи и новые записи — в диалогах.** Список остаётся на месте, контекст не теряется.
- **Вкладки карточки лида загружаются независимо** (свой Suspense): медленная история не задерживает карточку.
- **Основное меню на экранах 1024–1279 px — только иконки** (с подписью для экранного диктора и всплывающей подсказкой): иначе пункты налезали друг на друга.
