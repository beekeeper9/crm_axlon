# Дизайн-система

Образ — «точный инструмент»: спокойный тёмный интерфейс, один акцент для действий, статусы со строгими значениями, плотные рабочие списки без визуального шума. Продукт открыт 6–8 часов в день — каждое решение проверяем вопросом «помогает ли это быстрее понять и сделать».

Источник правды — токены в `app/globals.css`. В компонентах только токены (`bg-card`, `text-muted-foreground`, `text-success`), без произвольных цветов. Классы склеиваются через `cn` из `@/lib/utils` (знает собственные токены, например `text-meta`).

## Цвет

**Тёмная тема — основная.** Фон — мягкий графит, не чёрный: при долгой работе меньше утомляет и контраст текста не «режет».

| Слой | Токен | Где |
|------|-------|-----|
| Приложение | `background` (oklch 0.185) | Фон страницы |
| Рабочая панель | `card` (0.215) | Таблицы, списки, панели, карточки сделок |
| Всплывающее | `popover` (0.245) | Меню, селекты, диалоги, боковые панели |
| Подложка | `muted` | Заголовки групп (`bg-muted/35`), колонки доски (`/25`), неактивные элементы |
| Наведение и выбор | `accent` | Строка под курсором (`/50`), выбранный пункт |
| Границы | `border` (7,5 % белого), `input` (12 %) | Одна тонкая граница на панель (`ring-1 ring-border`), разделители строк |

Текст: `foreground` — данные; `muted-foreground` — подписи и вторичные значения. Контраст подписей ≥ 4.5:1 на `card`.

**Акцент (`primary`, кобальт 0.68)** — только для действий, выбора, фокуса и ИИ-блоков. Интерфейс не «синий»: акцент занимает малую площадь.

### Статусы — одно значение во всём продукте

| Тон | Токен | Значение |
|-----|-------|----------|
| success | `success` | Готово, состоялась, оплачено, рост |
| warning | `warning` | Требует внимания: нет следующего шага, нужен итог, демо-изменение |
| danger | `destructive` | Просрочено, отказ, ошибка, удаление |
| info | `primary` | Нейтральный рабочий статус (назначена, в работе) |
| neutral | `muted` | Служебные метки, архив |

Статус никогда не передаётся только цветом: рядом текст или иконка с подписью. Подложки статусов — цвет с прозрачностью 6–12 %.

## Типографика

Inter (кириллица), цифры одинаковой ширины (`tnum`) — колонки сумм ровные.

| Роль | Класс | Размер |
|------|-------|--------|
| Заголовок страницы | `text-xl font-semibold tracking-tight` | 20 px |
| Заголовок панели / секции | `text-sm font-semibold` | 14 px |
| Данные, строки таблиц | `text-sm` | 14 px, межстрочный 1.45 |
| Вторичный текст строки (дата, клиент, ответственный, итог) | `text-meta` | 13 px |
| Подписи полей, заголовки групп, метки | `text-xs` | 12 px |

Шрифт не уменьшаем ради плотности: плотность достигается отступами и структурой.

## Форма и отступы

- Радиусы: панели `rounded-xl`, кнопки и поля `rounded-lg`, бейджи `rounded-full`.
- Глубина — контрастом слоёв, без теней (кроме всплывающих элементов).
- Между панелью инструментов и данными — `space-y-3`; между крупными блоками страницы — `space-y-5`.
- Строки списков: 40–48 px (`py-2`–`py-2.5`); формы — `gap-4` между полями.
- Ширина: рабочие таблицы и доска — во всю ширину (до `max-w-screen-2xl`), списки задач, встреч и звонков — до `max-w-5xl`, чтобы глаз не бегал по пустому месту.

## Каркас и навигация

- Верхняя панель 56 px: логотип (стартовая страница роли), основные разделы роли, каталог «Все разделы», ИИ-помощник; справа «Демо-данные» и профиль. Менеджер: Мой день · Фокус · Продажи · После встречи · Встречи · Задачи. Руководитель: Кабинет РОПа · Продажи · Встречи · Задачи · Звонки. В каталоге группа «Контроль продаж» видна только руководителю.
- 1024–1279 px — основные разделы только иконками (подпись для экранного диктора и во всплывающей подсказке). Меньше 1024 px — весь каталог в выезжающей панели.
- Активный раздел — подложка `accent`.

## Общие компоненты (`components/shared`)

| Компонент | Назначение |
|-----------|-----------|
| `PageHeader` | Заголовок страницы, описание, действия справа |
| `Toolbar` | Одна строка над данными: поиск и фильтры слева, вид и главное действие справа; переносится на узком экране |
| `SegmentedLinks` | Переключатель-ссылки (`pill` — воронки, статусы, периоды; `tabs` — вкладки). Состояние в адресе |
| `SearchInput` | Поиск в адресе (`?q=`), с паузой при наборе, индикатором загрузки и очисткой |
| `FilterSelect` | Выпадающий фильтр в адресе; «Все …» убирает параметр |
| `ListPanel` + `ListGroup` | Рабочий список: одна панель, внутри группы с тонким заголовком и счётчиком (вместо карточки на группу) |
| `PaginationNav` | «1–25 из 43», назад/далее; из `count/limit/offset` |
| `UrlSheet` | Боковая панель, открытая параметром адреса (`?client=`, `?call=`): ссылкой можно поделиться, «назад» закрывает |
| `StatusBadge` | Статус с точкой и текстом |
| `PersonAvatar` | Инициалы сотрудника с полным именем для подсказки и диктора |
| `EmptyState` | Пусто: иконка, что случилось и что сделать |
| `ApiErrorState` | Ошибка загрузки по видам: не подключено к серверу, нет доступа, нет связи, сервер недоступен, неожиданный ответ; показывает код запроса |
| `DemoNotice` | Пунктирная янтарная плашка: действие работает только в демо, ничего не сохранено |
| `WidgetErrorBoundary` | Граница ошибок блока страницы: упавший блок не ломает остальные |
| `MetricHint` | «?» с определением метрики из книги определений |
| `PrintButton` | Печать / сохранение в PDF (карточка менеджера) |

Базовые примитивы — `components/ui` (shadcn на Base UI): Button, Input, Textarea, Select, Tabs, Dialog, Sheet, DropdownMenu, Popover, Tooltip, Table, Skeleton.

## Вход и выдача доступа

- **Вход:** одна карточка по центру — логотип, «Вход в аккаунт», логин, пароль с кнопкой показа, «Войти» (во время запроса — «Входим…» и блокировка). Ошибка — одной плашкой под полями. Сообщение об истёкшей сессии — над формой. В демо-режиме под карточкой — свёрнутая пунктирная подсказка с тестовыми входами.
- **Смена пароля:** та же рамка; при обязательной смене — пояснение и только «Выйти», без навигации CRM.
- **Создание аккаунта:** форма в одной панели; сверху строка «Будет создан аккаунт: роль · отдел». Роль не выбирается.
- **Результат:** отдельный экран с зелёной отметкой «Аккаунт создан», данными в обрамлении `success`, логином и паролем крупным моноширинным шрифтом, кнопками «Скопировать данные» (с подтверждением), «Создать ещё одного», «К списку сотрудников».

## Главные страницы

**«Мой день» (менеджер)** — по референсу владельца продукта; ширина до `max-w-6xl`.
1. Шапка: «Мой день», имя, переключатель месяца ‹ › (вперёд дальше текущего нельзя), «В работу».
2. «Сейчас» — плитки-ссылки; цвет плитки = статус; нулевые не показываются.
3. Оборот месяца (шкала с чертой «к сегодня по плану», прогноз, прирост, предоплаты и доплаты) и заработок с расчётом.
4. Четыре показателя: продажи, продажи / встречи (жёлтый, если ниже порога премии), средний чек, встречи состоялись.
5. «Что сделать сегодня» и «Сделки в приоритете» (только текущий месяц).
6. Показатели месяца (горизонтальные полосы) и «По дням» (SVG: ступенька накопительно, пунктир — план к дню по рабочим дням, столбики — за день; вкладки «Оборот / Продажи»).
7. Направления компании.

**«Кабинет РОПа»** — инструмент управления; ширина до `max-w-screen-xl`; только чтение.
1. Заголовок: «данные на HH:MM», рабочий день N из M; выключенная «Срез на планёрку» с пояснением.
2. Вкладки в адресе: Сегодня · План — факт · Встречи и звонки · Воронка.
3. «Сегодня»: на телефоне — светофор по менеджерам; **пульс отдела** (4 значения между линиями, без карточек) → **«Что требует внимания»** (3–5 строк: имя — проблема: число, иконка приоритета) и **«Перейти»** → **«Команда сегодня»**: таблица со светофором, причиной, кликабельными числами и строкой «Отдел»; отсутствие и тишина — отдельной строкой на всю ширину.
4. Секции кабинета — `CabinetSection` (заголовок и пояснение без рамки); рамку получают только таблицы и списки.
5. Подсказки определений — `MetricHint` («?» рядом с числом, всплывающее определение, пометка «определение согласуется»).

**Карточка менеджера** — для one-to-one и печати: строка фактов, оценки по дням (квадраты 2–5), активность по дням (полосы, красная черта — рабочий день без звонков), «На что сделать упор», дисциплина CRM, качество звонков (распределение оценок), «Послушать», сделки для дожима. Печать скрывает шапку приложения.

**Визуализации:** одна шкала прогресса с чертой ожидаемого; горизонтальные полосы для воронки и итогов встреч. Никаких графиков-дублей; без данных — прочерк и пояснение, а не выдуманное значение.

## Экранные паттерны

**Таблица** (`DealsTable` в «Продажах» и «Списке», таблица клиентов): закреплённая шапка, строка 44–48 px, строка целиком кликабельна (растянутая ссылка — работает с клавиатуры), числа справа, вторичная строка `text-meta`. Сортировка — ссылкой в заголовке колонки со стрелкой и `aria-sort`.

**Доска воронки:** колонки 272 px на подложке `muted/25`; шапка колонки — этап, количество, сумма. Карточка из трёх строк: название (2 строки максимум), следующий шаг с датой (красный — просрочен, янтарный — не назначен), сумма + метка + ответственный. Вся карточка открывает лид; меню «⋯» появляется при наведении, фокусе и всегда на сенсорных экранах. Над доской — итог воронки и подсказка, как менять этап.

**Очередь с панелью** («После встречи»): слева группы очереди, справа обработка выбранного; после сохранения выбор переходит к следующему. На узком экране обработка открывается выезжающей панелью.

**Карточка лида:** шапка (имя, этап, сумма, ответственный, «Позвонить») → путь по воронке → «Сейчас по сделке» (следующий шаг + «Что по сделке?» в одной панели) → вкладки. Справочная колонка «Клиент / Сделка / Другие сделки» — справа на всю высоту; на телефоне — между «Сейчас» и вкладками.

**ИИ-блоки:** иконка Sparkles, подпись «Разбор ИИ» / «Что по сделке?», подложка `primary/6`. Всегда отделены от фактических данных; на демо-данных подписаны «пример · демо»; без данных — объяснение, почему разбора нет.

## Состояния

| Состояние | Как показываем |
|-----------|----------------|
| Загрузка | Скелетон той же формы, что и данные; заголовок страницы виден сразу |
| Пусто / ничего не найдено | `EmptyState` с подсказкой, что изменить |
| Ошибка API | `ApiErrorState` по виду ошибки, без технических деталей, с кодом запроса |
| Нет прав | Действий нет (роль «Наблюдатель») или «Нет доступа» от backend |
| Операция не подключена | Кнопка выключена, подсказка «Станет доступно после согласования API» |
| Демо-изменение | Пометка «демо · не сохранено», `DemoNotice`, кнопка «Отменить» |
| Ошибка валидации | Текст под полем (`text-xs text-destructive`) и `aria-invalid` |

## Формы, диалоги, панели

- Подпись над полем всегда видна; плейсхолдер — пример значения.
- Диалог — короткие формы до 6 полей (задача, встреча, закрытие сделки). Боковая панель — просмотр без ухода со списка (задача, клиент, звонок).
- Затемнение под окнами — `black/55`; Esc и клик вне окна закрывают; фокус возвращается.
- Разрушительные действия — кнопка `destructive` с названием последствия («Закрыть как нереализованную»).

## Доступность

Видимый фокус у всего интерактивного (`:focus-visible` — кольцо `ring`). Меню, селекты, диалоги и вкладки — на Base UI, работают с клавиатуры. Иконки без текста имеют `aria-label`. Группы списков — `section` с заголовком; таблицы — `th scope`, `aria-sort`.

## Числа и даты

Только через `lib/format.ts`: `1 250 000 сом` (из десятичной строки API), `27 окт., 14:30`, `вторник, 27 октября` (часовой пояс компании), склонения через `pluralize`.
