# Передача контекста разработки

Состояние на 29.10.2026, коммит `189d62e` в `main` (https://github.com/beekeeper9/crm_axlon).
Документ собран по исходному коду, документации в `docs/` и истории коммитов. Пометка **«контекст разработки»** означает: известно из обсуждений с владельцем продукта, а не из кода.

Подробности — в профильных документах; здесь только сводка и указатели:
`docs/PRODUCT.md` (продукт, статусы разделов, открытые вопросы), `docs/ARCHITECTURE.md` (структура и правила модулей), `docs/API_CONTRACT.md` (согласованный контракт и предложения), `docs/DESIGN_SYSTEM.md` (дизайн-система), `docs/DECISIONS.md` (журнал решений), `CLAUDE.md` (правила работы ИИ-ассистента).

## 1. Назначение

CRM для управления результативностью отделов продаж малого и среднего бизнеса (5–50 менеджеров), рынок — Кыргызстан и СНГ, интерфейс на русском (`docs/PRODUCT.md`).
Две задачи: менеджеру — понять, что сделать сегодня по своим сделкам; руководителю — видеть положение дел в отделе и управлять результатом.
Этот репозиторий — **только frontend**. Backend — отдельный Python-сервис другого разработчика. *Контекст разработки:* владелец продукта называет backend Django; в коде и контракте фреймворк не зафиксирован, и frontend от него не зависит.

## 2. Стек (`package.json`)

Next.js 16.4 (App Router, Cache Components, Turbopack, `proxy.ts` вместо middleware), React 19.3, TypeScript strict, Tailwind CSS 4, shadcn/ui (стиль base-nova **на Base UI, не Radix**), Lucide, Zod 4, пакет `cn` (через `@/lib/utils`, знает токен `text-meta`).
Не установлены, хотя упомянуты в `CLAUDE.md` как целевые: React Hook Form, TanStack Query, Vitest, Playwright (решения — `docs/DECISIONS.md`). Recharts удалён; графики — простые SVG/CSS.
Next 16 отличается от привычных версий: перед изменениями сверяться с `node_modules/next/dist/docs/` (`AGENTS.md`).

## 3. Архитектура

- `app/` — только маршруты; данные, зависящие от запроса, читаются внутри `<Suspense>`.
  - `app/(crm)/` — рабочие разделы с верхней панелью;
  - `app/login`, `app/select-company`, `app/change-password` — страницы входа без навигации CRM.
- `features/<модуль>/` — схемы Zod (`schemas.ts`), репозиторий (`api/*-repository.ts`), компоненты; публичный API через `index.ts`.
- **Репозиторий с двумя реализациями:** mock (данные из `mocks/`) и http (через `apiRequest`); пока endpoint не согласован, http-метод выбрасывает `contract_pending`. Выбор — `NEXT_PUBLIC_DATA_SOURCE`.
- `lib/api/` — единственная точка HTTP (`client.ts`): Bearer, `X-Tenant`, snake_case ↔ camelCase, разбор ошибок с `request_id`, ротация refresh, пагинация `limit/offset`, деньги — десятичные строки.
- `lib/auth/`, `lib/session/` — токены, вход, текущий пользователь.
- `lib/permissions/` — роли и права интерфейса, перевод ролей backend.
- `components/ui` — примитивы shadcn; `components/shared` — общие блоки; `components/layout` — шапка и навигация.
- `config/` — env (проверка Zod), маршруты, навигация, локаль, демо-часы.
- `mocks/` — демо-данные и демо-«backend» аккаунтов; импортируются только mock-реализациями и слоем сессии демо-режима.

**Модули `features/`:**
- Рабочие пространства: `my-day`, `team-cabinet`.
- Продажи и клиенты: `focus`, `sales` (доска, таблица, «Список»), `leads` (карточка лида), `clients`, `after-meeting`.
- Работа менеджера: `tasks`, `meetings`, `calls`.
- Администрирование: `staff` (сотрудники и аккаунты), `team`.

## 4. Авторизация и роли

**Режим api** (согласовано с backend, `docs/API_CONTRACT.md`):
- JWT Bearer.
- Endpoint: `POST /api/v1/auth/token/`, `POST /api/v1/auth/token/refresh/` (ротация refresh), `GET /api/v1/me/`, `POST /api/v1/auth/logout/`, `POST /api/v1/auth/logout-all/`.
- Токены хранит сервер Next.js в httpOnly-cookie (`crm_access`, `crm_refresh`, `crm_tenant`); в backend уходят только `Authorization: Bearer` и `X-Tenant`.
- Обновление токена — в `proxy.ts` до рендера, один обмен на один refresh-токен.
- Проверено на локальной заглушке, **не на реальном backend**.

**Роли backend → интерфейса** (`lib/permissions/backend-roles.ts`):

| Backend | Интерфейс |
|---------|-----------|
| `owner` | Директор |
| `admin` | Директор (**смысл не подтверждён**) |
| `manager` | РОП |
| `sales_rep` | Менеджер |
| `viewer` | Наблюдатель |

Администратор платформы — не роль компании: **флага в `/me/` пока нет** (блокирующий вопрос).

**Стартовые страницы** (`homeRouteFor`):

| Роль | Страница |
|------|----------|
| Администратор платформы | `/platform` |
| Директор | `/company` |
| РОП | `/team` («Кабинет РОПа») |
| Менеджер | `/my-day` |
| Наблюдатель | `/sales` |

Запрещённые страницы проверяют право на сервере и перенаправляют на стартовую.

**Иерархия создания аккаунтов:** администратор платформы → директор (с новой компанией), директор → РОП (отдел своей компании), РОП → менеджер (только свой отдел). Роль назначает сервер. Временный пароль показывается один раз; при входе с ним — обязательная смена пароля.

**Области видимости:** менеджер получает только свои записи. В демо это правило применяет `mocks/scope.ts`; в реальном режиме это обязанность backend.

## 5. Demo mode и API mode

| | Demo (`NEXT_PUBLIC_DATA_SOURCE=mock`, по умолчанию) | API (`=api` + `NEXT_PUBLIC_API_BASE_URL`) |
|---|---|---|
| Вход | Тестовые аккаунты из `mocks/demo-accounts.seed.ts` (подсказка на странице входа), пароли хешируются scrypt, сессия — случайный токен в httpOnly-cookie `crm_demo_session` | Согласованные endpoint авторизации |
| Данные | Демо-наборы в `mocks/`, связаны между разделами; «сегодня» = 27.10.2026 (`config/demo-clock.ts`) | Почти все бизнес-endpoint не согласованы → экраны показывают «Раздел ещё не подключён к серверу» |
| Изменения | Только в браузере, с пометкой «демо · не сохранено» и «Отменить»; аккаунты — в памяти сервера до перезапуска | Кнопки выключены с пояснением, ничего не имитируется |

## 6. API-контракт

- **Согласовано:** транспорт, авторизация, формат ошибок, пагинация, деньги и даты, роли (`docs/API_CONTRACT.md`, часть 1).
- **Предложения, не согласованы:** формы данных всех бизнес-модулей, «Мой день», «Кабинет РОПа», сотрудники и аккаунты, смена пароля, дополнительные поля `/me/` (`full_name`, `is_platform_admin`, `must_change_password`) — там же, часть 2. Пути endpoint для них не придуманы, кроме явно помеченных предложений в разделе «Сотрудники и аккаунты».

## 7. Ключевые решения

Полный журнал — `docs/DECISIONS.md`. Главные:
- нет API-маршрутов Next.js и бизнес-логики backend во frontend;
- числа (план, прогноз, оценки, отбор) считает backend;
- два рабочих пространства — менеджера и РОПа — вместо одной главной;
- тёмная тема — основная;
- верхняя навигация, зависящая от роли;
- права в интерфейсе — только отображение, защита — на backend.

## 8. Реализовано (демо-данные)

- **Вход и аккаунты:**
  - вход, смена пароля, выбор компании, выход;
  - сотрудники и создание аккаунтов с выдачей временного пароля;
  - панель администратора платформы и страница «Компания».
- **Рабочие пространства:**
  - «Мой день» по референсу владельца;
  - «Кабинет РОПа»: сегодня, план — факт, встречи и звонки, воронка, карточка менеджера.
- **Разделы CRM:**
  - «Фокус»;
  - «Продажи» (доска с перетаскиванием и таблица);
  - «Список»;
  - карточка лида;
  - «Задачи», «Встречи», «После встречи», «База клиентов», «Звонки».

## 9. Известные ограничения

- Режим api проверен только на заглушке; реального backend frontend ещё не видел.
- Демо-аккаунты и сессии живут в памяти сервера и сбрасываются при перезапуске.
- Администратор платформы по прямой ссылке может открыть страницы CRM (данных там нет).
- Деактивации сотрудника и повторной выдачи пароля в интерфейсе нет.
- Нет автотестов (Vitest и Playwright не подключены).
- `README.md` устарел: описывает удалённую переменную `NEXT_PUBLIC_DEMO_ROLE`. Сейчас в демо — вход по тестовым аккаунтам.
- «План» менеджера (оборот к ориентиру, сом) и «план» РОПа (продажи, клиенты с первым платежом) — разные метрики; какая из них план, не решено.

## 11. Следующий этап — интеграция с backend

*Контекст разработки:* следующим этапом владелец продукта назвал интеграцию с Django backend. Порядок, который следует из кода:
1. Получить от backend-разработчика подтверждение контракта: флаг администратора платформы и поля `/me/`, endpoint сотрудников и смены пароля, затем бизнес-модулей, начиная с «Продаж» и «Задач».
2. Для каждого согласованного endpoint заменить `contractPending(...)` в http-реализации репозитория на `apiRequest(...)` с авторизацией из `getRenderAuth()` (чтение) или `getActionAuth()` (server actions), сверив схему Zod с реальным ответом.
3. Перевести демо-изменения (`editModeFor` → `demo`) на server actions с вызовом репозитория.
4. Проверить вход и ротацию токенов на реальном backend (настройка `NEXT_PUBLIC_DATA_SOURCE=api`, `NEXT_PUBLIC_API_BASE_URL`).

## 12. Согласованные правила работы

Из `CLAUDE.md` и *контекста разработки* (рабочий бриф владельца от 27.10.2026):
- Общение с владельцем — на простом русском, без лишнего жаргона.
- Работать по фазам: изучение → уточнение → план → реализация → проверка → отчёт.
- По важным решениям давать 2–3 варианта с плюсами, минусами и рекомендацией. Мелкие обратимые решения принимать самостоятельно.
- Разделять подтверждённые требования, допущения и открытые вопросы.
- Не создавать backend в Next.js, не выдумывать endpoint, держать демо-данные отдельно и не выдавать демо за реальные данные или сохранение.
- Секреты не класть в `NEXT_PUBLIC_*`.
- Не используй Radix API: проект на Base UI.
- Не копировать чужой бренд; не утверждать, что название или домен свободны, без проверки.
- **Коммитить и отправлять в GitHub только с разрешения владельца.**
- Поддерживать актуальными `docs/PRODUCT.md`, `ARCHITECTURE.md`, `DESIGN_SYSTEM.md`, `API_CONTRACT.md`, `DECISIONS.md`.
- После изменений — `npm run lint`, `npx tsc --noEmit`, `npm run build` и проверка в браузере; не утверждать, что проверено то, что не проверялось.

## 13. Запуск после клонирования

```bash
git clone https://github.com/beekeeper9/crm_axlon.git
cd crm_axlon
npm ci
cp .env.example .env.local
npm run dev
```

Откроется страница входа. Тестовые учётные записи демо-режима — в `mocks/demo-accounts.seed.ts`, их же показывает подсказка на странице входа.

Проверено 29.10.2026 на чистом клоне: `npm ci`, `npm run lint` и `npm run build` проходят. Отдельный `npx tsc --noEmit` в свежем клоне требует сначала сгенерировать типы маршрутов (`PageProps`, `LayoutProps`): `npx next typegen` — или один раз запустить `npm run dev` / `npm run build`.
